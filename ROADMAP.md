# Public Candidate Roadmap

Hearth and Code Governance Lab is a private, local prerelease candidate. This roadmap communicates direction; it does not promise dates, compatibility, support, admission, or release.

## Four horizons

### H0 — Local component evidence

- C1 authoring and grammar API: implemented locally.
- C2 pure response-writer core: accepted and implemented locally.
- C3 create-only disposable-vault provider: implemented and accepted through Worksheet 11.
- C4 native governance dashboard: implemented and accepted through Worksheet 13.
- C5 schema and workflow studio: implemented and accepted through Worksheet 14.
- C6 provider-neutral exchange: implemented and accepted through Worksheet 17.
- C7 provider-neutral semantic-interoperability specification: eight portable types and synthetic fixtures are implemented; every external adapter and canonical response port remains held.

Exit requires the applicable scratch-vault reviews. Local proof does not admit grammar, establish public support, or authorize release.

### H1 — Reviewed alpha candidate

- Preserve the accepted C3–C7 human dispositions and close any new severity-five findings.
- Preserve the accepted Obsidian 1.13.7 desktop lifecycle and runtime evidence and complete formal accessibility, computed-style, performance, and any additional claimed desktop-operating-system evidence. The accepted minimum remains 1.13.4; mobile remains unsupported for the first public candidate.
- Preserve the accepted `hearth-and-code-governance-lab` public plugin ID. Version 0.0.29 passed same-ID upgrade, rollback, disable/re-enable, duplicate-preflight, uninstall retention, and restoration in the disposable public-identity canary.
- Name the public owner, maintainer, security contact, supported platforms, response expectations, and release cadence.
- Review the bounded thirteen-preference settings candidate through the centralized presentation gallery; prove immediate open-render updates, one-question focus navigation, state retention, and that `data.json` is created or changed only after an explicit preference change and never weakens response or governance policy.

Exit requires explicit human acceptance. No remote, hosted CI, release, or Community directory action is implied.

### H2 — Interchange and convergence

- C6 provider-neutral LLM exchange is implemented as digest-bound copy/export and bounded paste/import only and was accepted through Worksheet 17.
- Provider-neutral convergence has a specification-only contract, eight public-safe fixture correspondences, and a no-effect TypeScript proof. Destination-specific adapters remain separately held.
- Direct model calls, authentication, network access, provider retention, cost, private response intake, and external-system implementation each require separate contracts and gates.

Exit requires destination semantic-owner and integration-owner review. The Obsidian plugin remains source-first and cannot silently update a canonical library or external knowledge system.

### H3 — Public release admission

- The exact 0.0.33 source and three package assets passed fresh locked reproduction, public-boundary verification, production dependency audit, bounded host review, and the exact public-ID lifecycle.
- Run and directly observe the admitted read-only hosted-assurance workflow before tagging or releasing.
- Route A authorizes source publication and the exact GitHub 0.0.33 release. Obsidian Community directory submission remains separately held.
- Publish only `main.js`, `manifest.json`, and `styles.css` as release assets, with an exact version tag and matching manifest.
- Keep response packets, private canonical sources, workspace state, credentials, and test-vault state out of the public repository and release.

Exit is a reviewed public release, not merely a green local build.

## Non-goals before public admission

- No automatic canonical write-back, frontmatter mutation, vault scan, telemetry, remote content, or background synchronization.
- No workflow execution, schema or vocabulary self-admission, arbitrary JavaScript, or Markdown-supplied code.
- No direct LLM/provider call, provider credential storage, spending, or data disclosure.
- No claim that synthetic tests prove real-host accessibility, compatibility, performance, privacy fitness, or security completeness.

## How decisions move

Each component follows **contract → proof → scratch-vault canary → human admission**. Acceptance of one component does not inherit another component's effect authority. The public release sequence and held effects are maintained in [`docs/maintainers/release.md`](docs/maintainers/release.md); private development packets and internal projectization records are not part of the public-source projection.
