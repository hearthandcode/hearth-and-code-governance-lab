# Project HCC governance

Create useful governance views and proposals while preserving source authority, privacy, provenance, and the no-automatic-apply boundary.

## Classify the requested projection

- Use the native dashboard for one selected note plus capped explicit one-hop metadata.
- Use an `hcc-view` for declarative data presentation with a semantic table fallback.
- Use governance actions for unapplied reviewed or verification proposals.
- Use `hcc-studio` for schema, vocabulary, migration, workflow, and dashboard design.
- Use `hcc-exchange` for manual digest-verified prompt export and in-memory returned-YAML validation.
- Stop if the request actually requires a vault index, provider call, workflow engine, or canonical writer.

## Bind sources

1. Name the exact source path, digest, authority, sensitivity, and review state.
2. Resolve only explicit relationship fields documented by the dashboard contract.
3. Cap native-dashboard references at twelve unique one-hop targets.
4. Exclude restricted, confidential, and secret linked records from copied reports.
5. Preserve missing or stale data as diagnostics.
6. Never crawl backlinks, folders, tags, graphs, or packet directories.

## Design the projection

1. Select semantics before visual form.
2. Preserve a title, summary, provenance trail, freshness state, and text/table equivalent.
3. Use only admitted selector aliases, view kinds, record fields, and guard kinds.
4. Keep governance proposals digest-bound and reviewer identity null until human attestation.
5. Keep studio transitions proposal-only with actors, guards, recovery, HumanGate, and receipts.
6. Keep exchange instruction and source-data sections separate.
7. Do not infer missing state or normalize authority silently.
8. Make prohibited effects visible near every action surface.

## Validate

- Validate views with the documented view parser and object validator.
- Validate studio packets with `HCC_AUTHORING_API.parseStudio`.
- Validate exchange packets before building a prompt.
- Supply trusted SHA-256 to prompt construction.
- Validate returned raw YAML in memory before rendering it.
- Run `npm run proof` for release-facing repository changes.
- In Obsidian, verify exact-source Open actions, selector empty states, copied reports, and no-write proposals.

## Refuse authority inflation

Never claim a projection is canonical, a proposal is applied, a document is human-reviewed, a record is verified, a workflow advanced, an LLM provider authorized, or an external adapter implemented without direct evidence and the corresponding human gate.

## Handoff

Return exact sources and digests, projection type, privacy exclusions, validation evidence, diagnostics, proposal-only effects, unsupported requested behavior, and one bounded human review or apply decision.
