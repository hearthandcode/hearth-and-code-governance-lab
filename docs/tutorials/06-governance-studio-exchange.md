# Lesson 7: Governance, studio, and exchange

## Goal

Use the advanced surfaces to orient provenance and design downstream systems without mutating sources, executing workflows, or calling providers.

## Native governance dashboard

1. Open one synthetic Markdown source note.
2. Run **Hearth and Code Governance Lab: Open governance dashboard for active note**.
3. Confirm exact source path, digest, relationship cap, and projection-only warning.
4. Inspect the four-stage provenance trail.
5. Cycle through the seven selectors and inspect table or empty-state semantics.
6. Open only the root or one admitted explicit reference.
7. Copy the projection report after reviewing its disclosure.
8. Prepare reviewed or verification proposals and confirm they remain unapplied.

## Schema and workflow studio

1. Begin with exact context sources, digests, authority, and sensitivity.
2. Declare record fields and vocabulary terms with stable IDs.
3. Bind invariants and guards to declared `record.field` IDs.
4. Describe migration compatibility, mappings, loss, and reversal.
5. Give transitions actors, declarative guards, recovery, HumanGate, and receipts.
6. Keep every effect `proposal-only`.
7. Validate and inspect ordered field-addressed diagnostics.
8. Copy normalized YAML only after semantic human review.

## Provider-neutral exchange

1. Embed only explicitly disclosure-approved source data.
2. Verify every source-content digest.
3. Build the fixed instruction/data-separated prompt packet.
4. Review and manually copy it.
5. Use a provider only under separate authority outside the plugin.
6. Paste one bounded raw `hcc-studio` YAML result.
7. Validate and render it in memory.
8. Return it as a proposal; do not admit or persist automatically.
