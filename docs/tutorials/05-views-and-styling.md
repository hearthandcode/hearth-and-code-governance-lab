# Lesson 6: Add views and styling

## Goal

Choose an honest accessible projection and verify it in Ember Circuit and Obsidian-native presentation.

## Minimal inline view

Consult `docs/reference/catalog.md` for the exact current kind and row schema. A view should have a title, summary, validated rows, and table-equivalent semantics. Use one explicit digest-bound source only when inline data is no longer appropriate.

## Eight-step design route

1. State the comparison, composition, sequence, relationship, distribution, process, or target question.
2. Select the smallest current view kind that answers it.
3. Prefer inline synthetic rows for tutorials.
4. If using a vault source, name one exact relative YAML or JSON path and SHA-256 digest.
5. Add a readable title, summary, labels, units, and uncertainty.
6. Validate unknown fields, ranges, IDs, and source freshness.
7. Inspect the semantic table and graphic for identical meaning.
8. If no current kind fits, propose a new grammar instead of forcing the data into another chart.

## Styling review

1. Start with Ember Circuit, the in-memory default.
2. Confirm content sits on an opaque shaded reading surface and the grid remains peripheral.
3. Inspect labels, plaques, legends, selected controls, focus rings, and errors.
4. Switch to **Toggle Ember Circuit / Obsidian-native presentation for this session**.
5. Repeat at normal zoom, 200 percent zoom, and a narrow pane.
6. Test a light and dark host theme when making a compatibility claim.
7. Test forced colors and reduced motion when those environments are available.
8. Record computed-style or assistive-technology evidence separately from visual impressions.
