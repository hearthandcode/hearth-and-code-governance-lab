# Lesson 8: Agent operation and recovery

## Goal

Let an LLM or coding agent work from a source checkout or installed vault without confusing those environments or broadening plugin authority.

## Repository mode

1. Read root `llms.txt`.
2. Select one matching package under `skills/`.
3. Read only the direct grammar, catalog, guide, and named task sources.
4. Create or edit only explicitly scoped project files.
5. Validate with the pure API or repository tests.
6. Run `npm run proof` before a release-facing handoff.
7. Report changed paths and test limitations.
8. Stop before Git, remote, publication, release, or submission unless separately authorized.

## Hearth & Code Hub mode

1. Start the agent with the canonical Hub as its working directory.
2. Invoke `$hearthandcode-governance-obsidian` and provide the bounded objective plus exact direct sources.
3. Require it to read root and destination charters and resolve the route from current configuration.
4. Require one canonical artifact owner, explicit audience and sensitivity, and proposal/projection authority.
5. Require the Hub path proposer and validator before a new or renamed governed artifact.
6. Let the agent write only the authorized Markdown paths; never `.obsidian`, plugin assets, or packets.
7. Open the exact path in the already configured Hub Obsidian vault and perform the human review.
8. Return only an explicitly copied response locator when asking the agent to prepare a separately governed intake or mapping proposal.

## Installed-vault mode

1. Inspect only the expected plugin manifest path.
2. Read the exact named Markdown note.
3. Preserve frontmatter, prose, IDs, and source-visible fences unless asked to alter them.
4. Do not install dependencies in the vault.
5. Do not enumerate packets; require an exact reload locator.
6. Do not edit `.obsidian`, plugin assets, packets, or canonical records without exact authority.
7. Hand back Markdown plus an Obsidian Reading view and Live Preview test route.
8. Keep persistence, canonical apply, provider, and publication effects explicit and held.

## Recovery table

| Symptom | Preserve first | Safe next action |
|---|---|---|
| Plugin fails to load | exact console error, manifest version, identity | stop asset changes and validate source bundle |
| Old plugin name appears | current manifest bytes and vault identity | reload app or restart Obsidian |
| Widget shows YAML diagnostic | original fence bytes and field path | repair only the diagnosed source field |
| Unsaved answers disappear | any copied final-review YAML or locator | reload one explicit created packet |
| Locator fails | exact two-line text and error code | correct path/digest; never search |
| Preview becomes stale | old preview and changed answer/source | prepare and review a new preview |
| Dashboard is empty | source frontmatter and explicit refs | accept empty state or edit source under separate authority |
| Duplicate identity appears | both exact manifest paths | disable and stop; do not delete or rename implicitly |
